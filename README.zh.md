## 0. 这份报告回答什么问题

白皮书中 Study 1 的目标：

> "在经延迟训练的模型和多隔室模型中，**延迟存储与神经元状态读写（而非脉冲数）**在匹配精度下占据可观能量份额。因此基于脉冲的估计会误判这两类模型。"

拆成两条可证伪的判据：

| 判据 | 定义 | 白皮书阈值 |
|---|---|---|
| **(a)** | 时间状态（状态存储 + 延迟存储 + 漏电）占单次推理能量的比例 | ≥ 10% |
| **(b)** | 按脉冲数或 SOP 的排序 ≠ 按完整模型的排序 | 至少一处比较 |

白皮书原文：

> "时间状态在**至少一个**类脑模型中占据不可忽略的能量份额，且仅按 SOP 的排序在**至少一处比较**中与完整模型排序不同。"

## 1. 三个模型

| 模型 | 来源 | 参数 | 神经元 | 轮数 | Checkpoint |
|---|---|---|---|---|---|
| **delay 256** | DelRec（`alexmaxad/DelRec`），可学习 per-synapse 延迟 | **239,124** | **532**（含输出 LIF） | **10** | best validation |
| **plain LIF** | PMSN（`xychen-comp/...-PMSN`），$d_{state}=1$ | 187,988 | 704 | 5 | 最后一轮 |
| **multi-compartment** | PMSN，$d_{state}=8$（4 个复数） | 200,660 | 704 | 3 | 最后一轮 |

**为什么选这三个**：对应白皮书的"SHD 上三个小型 SNN"——一个纯 LIF 基线、一个延迟训练网络、一个多隔室网络。PMSN 在 $d_{state}=1$ 时是一阶 IIR，等价于 LIF，因此与 $d_{state}=8$ 变体共用同一套代码；两者唯一的架构差别是隔室数量。

**为什么延迟网络宽度是 256**：per-synapse 延迟的参数成本是 $h^2$，若取 $h=352$，延迟网络将携带 430,164 个参数，而 PMSN 只有 188–201 K。取 $h=256$ 时为 239,124——与两个 PMSN 变体处于同一量级——同时仍达到 83.8–84.5% 测试精度。这一选择的精度代价记在 §10。

**为什么 PMSN 取最后一轮而非 best**：MC 在第 1 轮达峰，到第 2 轮回落约 1 点。取 best 会让它抬高 1.5–2 点、与 LIF 的差距拉大到 3–4 点，破坏精度匹配。

### 延迟是按神经元还是按突触？

**按突触。** `layers.7.recurrent_delays` 形状为 `(256, 256)`——每条**连接**一个值，因此神经元 `j` 的脉冲在 `t + 1 + d_ij` 到达目标 `i`（`delay_layers.py`：`synaptic_recdel`）。同一文件中的 `axonal_recdel`（每个突触前神经元一个延迟，形状 `(N,)`）与 `common_recdel`（每层一个标量）是另外两个变体；**我们用 `synaptic_recdel`**。

**这对能量计数的影响**：per-synapse 表存 $h^2$ 个延迟而非 $h$ 个，使延迟缓冲项扩大 256 倍（§5.3）。这是本报告的核算方式与 per-neuron 方式之间最大的差别。

### 前馈层带延迟吗？

**不带——唯一的延迟是第二个隐藏层的循环延迟。** checkpoint 中只有 18 个张量：三个 `Linear`、两个 `BatchNorm`，以及 `layers.7.recurrent_{weights,delays}`。没有 `dcls` / `.P` 条目，说明从未构建前馈延迟层；第一个隐藏层同样无延迟（`no_delay_in_first_layer=True`）。

**这是论文的 SHD 设定，不是遗漏**：DelRec 报告 SHD 时用的是"**朴素 LIF 神经元 + 无状态（瞬时）突触**"。

因此 `dcls` 专属的配置项（`max_feedforward_delay`、`no_delay_in_last_layer`、`DCLSversion`、`kernel_count`、padding、position scheduler）对本网络没有任何作用。

### 三个时间分辨率

同样 1.4 s 时长，不同帧长：

| T | 帧长 | delay | LIF | MC | 跨度 |
|---|---|---|---|---|---|
| 50 | 28.0 ms | 84.54% | 88.96% | 91.21% | 6.67 pt |
| **100** | **14.0 ms** | **84.30%** | 86.40% | 88.30% | **4.00 pt** |
| **140** | **10.0 ms** | **83.81%** | 87.10% | 88.96% | **5.15 pt** |

**延迟模型比两个 PMSN 变体低 4.0–6.7 点。** 这个差距是 per-synapse 参数预算的代价：若用 per-neuron 延迟、$h=352$，同一份代码可以到 86.56 / 87.24 / 87.99，但参数为 306,612。三个模型都落在同一精度带内（84–91%），满足白皮书"matched accuracy"的要求，但延迟网络始终是三者中最弱的。

## 2. 我们在原程序上改了什么，怎么训练的

### 2.0 统一时间轴

**三个模型、三个分辨率、共 9 次训练，全部使用同一种固定时长分箱：**

$$\text{duration} = \frac{1400\ \text{ms}}{T}\ \text{ms/frame}, \quad T \in \{50, 100, 140\}$$

**于是第 $t$ 帧在所有三个模型中都对应同一个物理区间 $[t \cdot \text{duration},\ (t+1) \cdot \text{duration})$。**

**这是可比性的前提**：两个上游代码库默认的分箱方式不同（DelRec 按帧数等分，PMSN 按 `linspace` 等分）。若不统一，"同一个 T"将意味着不同的帧长，SOP、延迟值和状态访问次数都会失去可比性。具体改动见 §2.1 与 §2.2。

### 2.1 DelRec：三处补丁

| # | 位置 | 改动 | 不改的后果 |
|---|---|---|---|
| 1 | `configs/perf_SHD.py` | 按 `time_step` 重新标定全部延迟超参 | 换分辨率时延迟语义漂移 |
| 2 | `src/delrec/datasets/loaders.py` | 用 `fixed_collate_T{T}` 替换 `pad_sequence_collate`；用 `duration=` 分箱 | **等分分箱（`frames_number`）会把精度从 87% 打到 70.40%** |
| 3 | `src/delrec/utils.py` | 时间维池化 `max` → `mean` | 与官方 checkpoint 的约定不一致 |

**为什么分箱必须用固定时长**：DelRec 的延迟是跨样本共享的离散帧数。若用等分分箱，一帧在不同长度的样本上覆盖不同的物理时长，延迟语义就被破坏。已逐元素验证：固定分箱与 `integrate_events_by_fixed_duration_shd(duration=...)` 完全一致。

### 2.1b 重构延迟网络的训练管线（上游 → 我们）

**上游行为：**

| 环节 | 原始 DelRec |
|---|---|
| 分箱 | `config.time_step` 传给 `integrate_events_by_fixed_duration_shd(duration=...)`，但下游 `collate_fn=pad_sequence_collate` 保留每个样本的实际帧数 |
| Batch 组装 | 变长 padding，**同一 batch 内样本帧数不同** |
| 时间维池化 | `m, _ = torch.max(output, 0)`（沿时间取 max） |
| 延迟超参 | 硬编码在 `@10 ms`：`max_rec_delay=30`、`max_feedforward_delay=250//time_step`、`sigma_init=10.0`、`init_recdel_offset=10`、`delay_std_init=15` |

**我们改成了：**

| 环节 | 改后 | 原因 |
|---|---|---|
| 分箱 | **固定 `duration = 1400/T` ms**，过长裁剪、过短零填充 | 保证"一帧 = 固定物理时长" |
| Batch 组装 | **`fixed_collate_T{T}`：裁剪 / 零填充到固定 T 帧** | 延迟以帧计；若 batch 内帧数不同，同一延迟值对应不同物理时长 |
| 时间维池化 | **`m = torch.mean(output, 0)`** | 与官方 checkpoint 的约定一致 |
| 延迟超参 | **全部按物理时间重推**（除以 `time_step`），见下表 | 延迟语义在各分辨率下保持在 300 ms / 250 ms / 100 ms / 150 ms |

**注意 `max_feedforward_delay` 原本就写成 `250//time_step`——它已经做了物理时间换算，但另外四项硬编码在 `@10 ms`。只改 `time_step` 而不重推这五项，会让 T=50 下的有效延迟翻倍以上。**

**延迟超参以帧为单位固定，而不是按物理时间推导：**

| 参数 | T=50 | T=100 | T=140 |
|---|---|---|---|
| `time_step` | 28 | 14 | 10 |
| `max_feedforward_delay` | 9 | 17 | 25 |
| `max_rec_delay` | 30 | 30 | 30 |
| `sigma_init` | 10.0 | 10.0 | 10.0 |
| `init_recdel_offset` | 10 | 10 | 10 |
| `delay_std_init` | 15 | 15 | 15 |
| `batch_size` | 40 | 40 | 40 |

**上游是按固定物理预算推导的**（`300 ms / time_step` → 11 / 21 / 30，`100 ms / time_step` → 3.5 / 7.0 / 10.0，等等）。**本研究改为固定帧数**，于是延迟范围在各分辨率下是恒定的帧数，缓冲深度也保持可比。

唯一的例外是 `max_feedforward_delay`，它确实遵循物理时间规则——但**在本网络中毫无作用**，因为网络不含 `dcls` 层。

这些值存放在 `training_bundle/delrec/config_T{50,100,140}.py`，每个分辨率一个文件。

### 2.2 PMSN：两处改动

| # | 改动 | 不改的后果 |
|---|---|---|
| 1 | `np.linspace` 等分分箱 → 固定 `duration = 1400/T` ms | 它的"一帧"与 DelRec 的对不上，两个模型族无法在同一 T 下比较 |
| 2 | `bn=False` → `bn=True` | checkpoint 是按 `bn=True` 训练的，不匹配会在 `load_state_dict` 报错 |

**PMSN 是连续时间常数 SSM，对分箱方式不敏感**（已验证：切换后精度不变）。分箱改动纯粹是为了与延迟网络对齐时间轴。

## 3. Mesh 设计与参考

### 3.1 拓扑

| 配置 | 核数 | 路由 | 跳数范围 |
|---|---|---|---|
| 2×2 | 4 | 2D mesh，XY 维序路由 | 1–2 |
| 4×4 | 16 | 同上 | 1–6 |
| 8×8 | 64 | 同上 | 1–14 |

**跳数 = 曼哈顿距离**（最短路表在 `net/topology.py`）。

**不设 2 核配置**：1D 直连的跳数分布退化（全为 1），在单一拓扑族下无法与重尾的 2D mesh 比较，故移除。

### 3.2 神经元到核的映射

**顺序映射**（Loihi Nx SDK 与 SpiNNaker 编译器的默认做法）：

$$\text{core}(i) = \left\lfloor \frac{i \cdot n_{cores}}{n_{total}} \right\rfloor,
\quad n_{total} = 532 \text{（delay）} \ / \ 704 \text{（PMSN）}$$

**每个模型用自己的神经元数做映射**，因此延迟网络（532）与两个 PMSN 变体（704）的核分配略有不同。

**这不是通信优化算法；它是确定性、可复现、与连接无关的基线。**

**已知代价**：输出层只有 20 个神经元，全部落在最后一个核上。

| Mesh | hidden1 所在核 | hidden2 所在核 | **out 所在核** |
|---|---|---|---|
| 2×2 | 0–1 | 1–3 | **3** |
| 4×4 | 0–7 | 7–15 | **15** |
| 8×8 | 0–30 | 30–61 | **61–63** |

**因此 hidden2 → out 的流量汇聚到 1–2 个核上，形成结构性热点。** 这属于"未优化的上界"的一部分，见 §8。

### 3.3 通信如何计数

**一个脉冲被发送到"所有持有下游神经元的核"（multicast 语义）；跳数 = 到每个目标核最短路长度之和。**

由于 hidden1 与 hidden2 全连接，每个 hidden1 脉冲确实必须到达所有持有 hidden2 神经元的核，因此 multicast 语义是恰当的。

**然而，按目标核累加路径长度等价于对每个目标独立做 unicast，这是真实 multicast 树的上界**（见 §8）。

### 3.4 单核容量

| 项目 | 8×8 下的值 | Loihi 上限 |
|---|---|---|
| 每核神经元 | 11（hidden1/hidden2），20（out） | 1,024 |
| 每核突触 | 约 3,800（hidden2），7,040（out） | 128 K |

**远低于上限；容量不是约束。**

## 4. 计算方法

### 4.0 为什么自建解析模型而不是用现成模拟器

**我们调研了现成的开源 SNN 能耗评估工具，没有一个符合本研究的要求。** 需求很窄但很具体：一个 45 nm **数字 CMOS** 成本模型，覆盖 Study 1 的五类（含**延迟存储**与**存储状态漏电**），支持**可学习延迟**与**多隔室**神经元，并能由两个上游代码库的 PyTorch 模型驱动。

| 工具 | 建模对象 | 为何不适用 |
|---|---|---|
| **SpikeSim**（Yale） | 模拟 IMC 交叉阵列（RRAM/SRAM），65 nm | 架构不匹配：交叉阵列 tile 与 ADC/DIFF 流水线，不是数字 MAC 阵列。其延迟模型（$\alpha$、`passes`）在这里没有对应物 |
| **NeuroSim** | 模拟/IMC 交叉阵列 | 与 SpikeSim 相同的不匹配 |
| **BookSim** | NoC 延迟与吞吐 | 只建模互连；不含 SNN 能耗、不含状态或延迟存储 |
| **snnTorch / SpikingJelly** | 训练框架 | 最多报 MAC/SOP 计数，无硬件能耗模型 |
| **Lava / Nx SDK** | 面向 Loihi 1 | Loihi 1 的神经元模型是 CUBA LIF，**恰好两个内部状态变量**——突触响应电流 $u_i(t)$ 与膜电位 $v_i(t)$（Davies et al. 2018, p.3）。我们的多隔室模型需要 **4 隔室 × 2 个实状态变量 = 8**，无法映射到 Loihi 1。详见下文 |
| **NeuroBench** | 与硬件无关的指标 | 明确只提供 SOP 与激活稀疏度，**不提供**硬件能耗 |
| **SNNToolBox / N2D2** | 量化与编译 | 能耗模块粗糙（仅 SOP） |

**结论**：没有任何现成工具同时具备 (i) 45 nm 数字 CMOS 成本基准、(ii) 延迟存储与状态存储的分项核算、(iii) 对可学习延迟与多隔室模型的支持、(iv) 从这两个训练代码库接入的路径。**因此自建一个透明的解析模型，每一项都是"计数 × 文献单价"**——这也正是白皮书 Study 1 Setup 所要求的（"a transparent CMOS energy model with characterized per-operation, per-access, and per-bit-of-storage costs"）。

#### Loihi 1 的结构性限制（为何不能复用它的能耗数字）

**除了工艺节点，还有三个硬性架构约束使 Loihi 1 无法作为本研究的平台：**

| 约束 | Loihi 1 | 本研究需要 |
|---|---|---|
| **每神经元状态变量** | **2** 个——$u_i$（突触电流）与 $v_i$（膜电位），固定 CUBA LIF（Davies et al. 2018, p.3）。树突隔室确实存在，但每个隔室携带相同的固定 $u/v$ 动态；无法实例化任意 $N$ 阶状态空间模型 | 4 隔室 PMSN 需要 **8** 个（4 隔室 × 实部 + 虚部）。根本装不下 |
| **突触延迟** | 5 元组 $(i, j, \text{wgt}, \text{dly}, \text{tag})$ 中的每突触字段——每个突触挂一个延迟值 | **每神经元**一个可学习延迟，配半宽 $\sigma$ 的三角核（DelRec）。语义不同；Loihi 无法表示核的展宽 |
| **时序模型** | 异步，无全局时钟（$t_{NoC}$ 不是设计参数）；每个核独立迭代其神经元隔室 | 时钟驱动、按时间步更新，显式的 $t_{inf} = \text{MAC 计数} / (n_{cores} F)$ |

**复用 Loihi 实测值的后果：**

- **23.6 pJ 每突触脉冲操作** 是端到端实测值。它打包了权重 RMW、状态更新、神经元更新与路由，**无法分解**到 Study 1 的五类（突触 / 通信 / 延迟 / 状态 / 漏电）。用它会把 Study 1 恰恰要测量的区分抹平。
- **81 / 52 pJ 每神经元更新** 同样包含对神经元状态组的完整 RMW 环，无法分离延迟缓冲项与多隔室项。
- **3.0 / 4.0 pJ 每 tile hop** *可以*用——这是唯一一个其范围（路由器 + 链路，一个 flit）与我们 `flit_hops` 定义匹配的量，我们把它作为 $E_{hop}$（§4.4），并与 Gorski 的 45 nm 路由器功耗交叉校对。

**所以诚实的立场是**：Loihi 1 提供了一个可迁移的单价（$E_{hop}$），以及在定性上确认"大 mesh 下通信占主导"，但它既装不下延迟训练模型，也装不下多隔室模型，其复合能耗数字无法分解成本研究所需的核算。

**这是真实的限制，不只是便利问题**：一个周期精确的模拟器还会额外刻画缓冲争用、仲裁与拥塞，这些目前都在模型之外（§8.2、§8.3）。这也意味着*绝对*数字无法与已发表的基于工具的结果直接比较。

### 4.1 时间模型

$$t_{inf} = \frac{\text{SOP} + N_{neur} \cdot T \cdot d_{state}}{n_{cores} \cdot F \cdot \text{par}}, \quad F = 2\ \text{GHz},\ \text{par} = 1$$

**物理含义**：总 MAC 数除以（核数 × 频率 × 每周期并行度）。

**`par = 1` 意味着每核每周期完成一个 MAC——这是一个乐观假设**，见 §8 限制 1。

### 4.2 Study 1 的五类

按白皮书 Study 1 Procedure（p.12）：

| # | 类别 | 公式 |
|---|---|---|
| 1 | **突触操作** | $\text{SOP} \times E_{AC} + N_{neur} T d_{state} \times E_{MAC}$ |
| 2 | **通信** | $fh \times E_{hop}$ |
| 3 | **延迟存储** | $N_{access} \cdot T \cdot 2 \times E_{access}$，其中 $N_{access}=256$（§1） |
| 4 | **状态存储** | $N_{neur} T d_{state} \cdot 2 \times E_{access}$ |
| 5 | **漏电** | $bits_{state+buffer} \times P_{leak} \times t_{inf}$ |

**延迟存储是两种延迟变体唯一不同的类别。** $N_{access}$ 是**每时间步的访问端口数**，不是存储的延迟个数：两种变体下缓冲都是 `(B, 256, L-1)`，所以每步都只触碰一行 256 个 slot（`delay_layers_pytorch.py`：`y_window` 对 `axonal_recdel` 与 `synaptic_recdel` 都是 `(N, L-1)`）。

**存储的延迟*个数*确实不同**——per-synapse 是 $h^2 = 65{,}536$，per-neuron 是 $h = 256$——这个数量驱动的是第 5 类中缓冲的**比特**成本，不是这里的访问成本。§5.3 给出定量。

**$\int P_{idle}dt$、时钟树、数据转换与特征提取不计入**——那是白皮书完整的 §4.3 公式，Study 1 不需要。

### 4.3 权重漏电单列

**权重占据 SRAM 并漏电，但它们与时间机制无关。** 把它们并入"时间状态份额"会稀释信号（它们占全部比特的 73–99%）。

**因此权重漏电单列一栏，不计入判据 (a) 的分子。**

## 5. 计数结果（不含单价）

### 5.1 计数约定的文献依据

**四个计数定义全部来自 Dampfhoffer et al. 2023 的 LIF+inst 能耗模型（Eq. 3.4 与 3.7）：**

**突触操作（Eq. 3.4, L2007）：**

$$E_{IF+inst} = N_{syn} \cdot N_{spikes/syn} \cdot (E_R^{weight} + E_R^{state} + E_W^{state} + E_{AC})$$

**每时间步神经元更新（Eq. 3.7, L2037–2038）：**

$$E_{LIF+inst} = \underbrace{N_{syn} N_{spikes/syn}(\cdots)}_{\text{event-driven}} + \underbrace{N_{neur} T (E_R^{state} + E_W^{state} + E_{MAC})}_{\text{clock-driven}}$$

**四个计数的出处：**

| 计数 | 我们的公式 | Dampfhoffer 依据 |
|---|---|---|
| **SOP** | 脉冲 × fanout | Eq. 3.4 中的 $N_{syn} N_{spikes/syn}$ 项 |
| **神经元操作** | $N_{neur} \times T \times d_{state}$ | Eq. 3.7 中的 $N_{neur} T$；隔室数 $d_{state}$ 是我们在 PMSN 上的扩展 |
| **状态访问** | 神经元操作 **× 2** | Eq. 3.7 中的 $E_R^{state} + E_W^{state}$；L2032–2034 写道"**读取状态、与常数相乘、再写回结果**" |
| **缓冲访问** | $256 \times T \times 2$ | 无直接来源；由状态访问的读写模式类比（读取即将过期的 slot + 写入当前脉冲） |

**为何只用 Eq. 3.7 的第二项而非第一项**：Dampfhoffer L2039–2044 说明这是两条**互斥**的实现路线——第一条是事件驱动（只在脉冲到达时更新状态），第二条是时钟驱动（每步更新全部神经元），原文指出"每时间步的更新更高效"。我们的模型是时钟驱动的（`delay_layers_pytorch.py:95` 的 `single_step_forward`），所以只适用第二项。

**以下所有数字均为 **全部 2,264 个 SHD 测试样本** 的单样本平均。**

**注意权重读让判据 (b) 变*弱*、而不是变强**：对每次操作收权重读会抬高 SOP 在总量中的占比，使仅按 SOP 的排序*更接近*完整模型。这是核算方式的限制，不是模型的限制。

| **SOP** | LIF(4.71M) < delay(4.83M) < MC(5.24M) | **第二**（实际**最贵**） |
| **完整模型** | LIF(6.28) < MC(20.30) < **delay(27.31)** | 最贵 |

**两种估计在这里指向同一个方向，而且都错了。** 脉冲数看见了延迟网络的稀疏（5,301 对 LIF 的 13,930），但看不见它的缓冲成本；SOP 看见了 256 的循环 fanout，但看不见延迟表。完整模型把 delay 定在 27.31 µJ，是 LIF 的四倍。

**漏掉的是延迟表，不是延迟本身。** §5.3：65,536 个延迟 × 44 个 slot = 2.88 Mbit，仅其漏电就占那 27.31 µJ 中的 21.08。脉冲数和 SOP 都不知道这张表的存在。

### 7.2 多隔室成本只在完整模型里可见

| T=100，2×2 | delay | LIF | **MC** |
|---|---|---|---|
| 脉冲数 | 5,301 | 13,930 | 15,672 |
| SOP | 4.83M | 4.71M | 5.24M |
| **状态** | 1.064 | 1.408 | **11.264（8.0×）** |
| **漏电** | **21.075** | 0.160 | 1.556 |
| 完整模型 | **27.31** | 6.28 | 20.30 |

**$d_{state}=8$ 把状态访问次数与比特数同时乘以 8，而 SOP 里没有这个因子**——MC 的 8 倍状态成本对 SOP 完全不可见。

**对称地，延迟表对所有简化估计都不可见。** 这两个模型昂贵的原因完全不同：MC 因为每神经元 8 个实状态值，延迟网络因为每突触 65,536 项的延迟表。这一点值得直说——基于脉冲或 SOP 的分析会把*两者*都判为便宜。

### 7.3 大 mesh 下通信超过状态

| T=100，8×8 | delay | LIF | MC |
|---|---|---|---|
| 通信 | 3.120 | 7.749 | 9.018 |
| 通信占比 | **29%** | **56%** | **33%** |

**在 64 核上延迟网络又变成最便宜的（10.61 对 13.73 与 27.69）。** 它的跳数只有 LIF 的 40%，因为它发放 5,301 个脉冲而 LIF 是 13,930——per-synapse 延迟抑制了冗余活动。

**但它在 8×8 上的能量优势来自三项同时下降**，不只是通信：缓冲漏电降到 1.32 µJ（2×2 时是 21.08，因为 $t_{inf}$ 缩小 16 倍），通信 3.12 对 LIF 的 7.75，突触项 4.59 对 MC 的 7.31。

**注意相对 2×2 的反转**：在 2×2 上延迟网络是三者中*最贵*的（27.31 对 20.30 与 6.28），到 8×8 反而最便宜。mesh 大小改变了哪个项占主导，而延迟模型是对此最敏感的那个。

### 7.4 时间分辨率的影响

**这一版不再呈单调趋势。** delay 在 T = 50 / 100 / 140 下为 84.54 / 84.30 / 83.81%，0.7 点内基本持平，且在最细帧上略有*下降*。两个 PMSN 变体都在 28 ms（T=50）达峰。

| | 机制 | 表现 |
|---|---|---|
| delay | 离散帧级延迟 | 本版本**不敏感**；256² 个延迟可以吸收任意给定的分辨率，精度变化 <0.7 点 |
| PMSN | 连续时间常数 | **在 28 ms 达峰**，最接近 SHD 音素时长 50–200 ms |

**早先"delay 偏好更细分辨率"的结论在改用 per-synapse 后不再成立。** 在 $h=352$ + per-neuron 延迟时，模型确实随帧变细而变好（86.56 → 87.24 → 87.99）。改用 per-synapse 表、$h=256$ 后，这个效应消失——延迟网格已经足够密，帧分辨率不再是限制因素。现在限制精度的是参数预算，不是延迟粒度。

## 8. placement 与成本模型的选择会影响结果

**这是本报告最重要的前提说明：绝对数字取决于以下建模选择，每一条都有替代方案。**

### 8.1 placement 未优化

**顺序映射把整个输出层放在最后一个核上（4×4 的核 15，8×8 的核 62–63）。**

**影响**：hidden2 → out 的流量形成热点，跳数被系统性高估。**一个通信感知的 placement（例如把输出层摊开）会降低 flit_hops，从而降低通信项。**

**在 8×8 下通信项占总量的 29–56%，所以这一选择在这里影响最大。**

### 8.2 multicast 按 unicast 上界计算

**当前跳数 = 到各目标核最短路的和，等价于对每个目标独立发送一份 unicast。**

**真实的 NoC multicast 使用复制树，只在路径分叉处复制。**

**影响**：flit_hops 被高估 2–3 倍，通信项按比例放大。**三个模型被同一个因子放大，因此排序不受影响。**

### 8.3 同一时间步内的多个脉冲未合并

**每个脉冲独立计数。物理上，同一时间步内来自同一源核、发往同一目标集的多个脉冲可以共用一帧 flit 载荷。**

**影响**：方向与 §8.2 相同，进一步高估通信。

### 8.4 时间模型的 par = 1 无文献依据

**假设 32-bit 浮点 MAC 在 2 GHz 下 1 个周期完成。**

**影响**：若一个 MAC 实际需要 4 个周期，$t_{inf}$ 会大 4 倍，$P_{leak} \times t_{inf}$ 按比例放大。

**但 Study 1 的漏电只占 0.2–3.7%（不含权重），所以判据 (a)(b) 不受影响。权重漏电（T=100、2×2 时为 55.60 µJ）受影响很大，但它是单列报告的。**

### 8.5 工艺节点混用

| 参数 | 节点 |
|---|---|
| $E_{AC}$ / $E_{MAC}$ / $E_{access}$ / $P_{leak}$ | **45 nm** |
| $E_{hop}$ | **14 nm**（Loihi） |

**按节点缩放（14→45 nm，约 2.75 倍），$E_{hop}$ 约为 9.6 pJ/hop，通信项相应放大。**

### 8.6 权重读项假设无复用（§5.5）

**每次突触操作都被收一次完整的 SRAM 访问（10 pJ）以取它的 32-bit 权重。真实核会读整条 SRAM line，并在连续几次突触操作中复用。**

**影响**：设复用因子为 $R$，该项按 $1/R$ 缩放。取 $R=4$（128-bit line 供四次 32-bit 操作）时，T=100 延迟模型的权重项从 48.31 µJ 降到 12.08 µJ，总计从 27.31 升到 39.39 µJ，其时间状态份额从 **82.9% 降到 57.5%**——仍是主导项，但数字大不相同。常驻口径对应 $R=\infty$（82.9%）。

**所以 §5.5 的"权重在 SRAM"一栏是最坏情况，不是预测。** 两种口径夹住真相：权重复用才是决定"时间状态是否重要"的关键，而这本身是一个架构问题，正是白皮书 Thrust 3（存储层级）要回答的。

### 8.7 如何读这些数字

**可信的：**
- 三个模型的相对排序（在同一组建模假设下）
- 时间状态份额的量级（几十个百分点，不是 1% 也不是 90%）
- "简化估计会误判排序"这个结论

**不可信的：**
- 绝对 µJ 值（可能差 2–3 倍）
- 任何"比芯片 Y 高效 X 倍"式的跨工作比较

## 9. 复现方法

### 9.1 依赖

- Python 3.11+、PyTorch、h5py、numpy、matplotlib
- DelRec 源码（`alexmaxad/DelRec`）与 SHD 数据集
- 三个模型的 checkpoint（路径见 §9.4）

**训练在 Google Colab 默认环境中完成；测量在本地 CPU 上运行（`map_location="cpu"`）。除 `spikingjelly@d4fee3a1` 外，未锁定精确版本。**

### 9.2 从零开始

**训练**——9 次训练由 `training_bundle/` 驱动，其中已包含全部改好的文件，**无需任何打补丁步骤**：

```bash
unzip -q training_bundle.zip -d /content
bash /content/bundle/runs/02_delay_T100.sh      # delay   (01..03)
bash /content/bundle/runs/06_pmsn_lif_T100.sh   # PMSN    (04..09)
# ... 共 9 次；见 patches/TRAINING.md
```

**测量**——读取 `checkpoints/` 下九个 checkpoint 并写出结果 JSON：

```bash
python scripts/study1_measure.py --n -1 --save results/study1_h256_measure_full.json
```

`--n -1` 是默认值，意为全部 2,264 个测试样本；`--n 10` 是快速冒烟测试。checkpoint 路径相对于 `scripts/` 解析，因此交付目录可以整体移动。两个外部路径由环境变量给出：

```bash
export DELREC_ROOT=/content/DelRec     # 默认：D:\DelRec
export SHD_TEST_H5=/content/DelRec/Datasets/SHD/extract/shd_test.h5
```

```bash
# 3. 作图（约 5 秒），读取 results/study1_h256_measure_full.json
python scripts/plot_study1.py

# 4. 一致性检查：10 样本子集 vs 已保存的全量 JSON（约 2 分钟）
python scripts/check_10_samples.py
```

**三个脚本都相对自身位置定位输入**，因此移动目录后无需修改任何路径。

### 9.3 数据可靠性

**交叉验证，10 样本 vs 2,264 样本：**

| 模型 | T | SOP 比值 | flit_hops 比值 |
|---|---|---|---|
| delay | 50 / 100 / 140 | 1.014 / 1.009 / 1.019 | 1.000 / 0.987 / 1.020 |
| LIF | 50 / 100 / 140 | 1.014 / 1.017 / 1.011 | 1.014 / 1.014 / 1.003 |
| MC | 50 / 100 / 140 | 1.017 / 1.011 / 1.013 | 1.019 / 1.004 / 1.012 |

**全部偏差 <2.0%，说明 2,264 样本的平均值已收敛。**

### 9.4 Checkpoint 位置

九个 checkpoint 全部随本交付物提供，位于 `checkpoints/`：

```
checkpoints/
├── delay_T50/      best.pth  last.pth  config.json  final_test.json
│                   final_delays.npz  init_delays.npz

├── pmsn_lif_T50/   checkpoint.pth  log.txt
├── pmsn_mc_T50/    checkpoint.pth  log.txt
├── pmsn_lif_T100/  checkpoint.pth  log.txt
├── pmsn_mc_T100/   checkpoint.pth  log.txt
├── pmsn_lif_T140/  checkpoint.pth  log.txt
└── pmsn_mc_T140/   checkpoint.pth  log.txt
```

**所有路径都相对 `scripts/study1_measure.py` 解析**，因此目录可整体移动或复制而无需改动。只有 DelRec 仓库与 SHD 的 `.h5` 文件是外部的——若它们不在默认位置，设置 `DELREC_ROOT` 与 `SHD_TEST_H5`（§9.2）。

**`delay_T50` 与 `delay_T140` 缺少 `train_res.csv` / `val_res.csv`**：那两次训练从 Colab 导出时没有带训练日志。这不影响任何报告数字——测量只读 `best.pth` 与 `final_delays.npz`——但意味着这两个分辨率没有逐轮曲线可用。
